# MVP Scope — Restaurant Order Management System

> **Status**: APPROVED AND FROZEN
> **Version**: 1.0
> **Date**: August 2026

---

## 1. MVP Definition

The Minimum Viable Product (MVP) is the smallest set of features that delivers value to the target users (restaurant staff) while exercising the complete DevOps pipeline. The MVP is scoped to be achievable by a solo developer in 15 weeks, with roughly 6 weeks dedicated to application development and 9 weeks to DevOps tooling and pipeline setup.

---

## 2. In-Scope Features (Frozen)

### Feature F1 — Item Catalogue Management

- **Description**: Restaurant manager can add, view, edit, and delete menu items
- **User**: Restaurant Owner / Manager
- **Priority**: Must Have
- **Sprint**: Week 5 (Feature Branch 1)

**Functional Requirements:**
- Add a new menu item with: name, category (Starter, Main Course, Dessert, Beverage), price, availability status
- View all menu items in a sortable table
- Edit any field of an existing menu item
- Delete a menu item (soft delete preferred)
- Validate inputs: name required, price > 0, category from predefined list

---

### Feature F2 — Create / Update Order (Transaction)

- **Description**: Waiter can create a new order for a table, add items, modify quantities
- **User**: Waiter / Front-of-House Staff
- **Priority**: Must Have
- **Sprint**: Week 6

**Functional Requirements:**
- Create a new order with: table number, list of items with quantities
- Auto-calculate order total based on item prices × quantities
- Update an existing order: add/remove items, change quantities (only if status is "Placed" or "Preparing")
- Assign initial status "Placed" on creation
- Record creation and last-updated timestamps

---

### Feature F3 — Order Status Tracking

- **Description**: Staff can update and view the status of each order through its lifecycle
- **User**: Kitchen Staff, Waiter, Manager
- **Priority**: Must Have
- **Sprint**: Week 6

**Functional Requirements:**
- Order status lifecycle: Placed → Preparing → Ready → Served → Closed
- Only valid forward transitions allowed (cannot go from "Ready" back to "Placed")
- Each status change records a timestamp
- Kitchen view shows orders grouped by status
- Visual indicators (colour-coded badges) for each status

---

### Feature F4 — Search and Filter

- **Description**: Users can search menu items and filter orders by various criteria
- **User**: Manager, Waiter
- **Priority**: Should Have
- **Sprint**: Week 6

**Functional Requirements:**
- Menu search: Search by item name (partial match), filter by category, filter by availability
- Order filter: Filter by status, filter by date range, search by order ID or table number
- Results update dynamically (client-side filtering or API query params)
- Show "No results found" message when filters return empty

---

### Feature F5 — Exception Alerts

- **Description**: System automatically generates alerts for operational exceptions
- **User**: Manager, Kitchen Staff
- **Priority**: Should Have
- **Sprint**: Week 6

**Functional Requirements:**
- Out-of-stock alert: Triggered when an order includes an item marked as unavailable
- Stale order alert: Triggered when an order has been in "Placed" or "Preparing" status for more than 30 minutes
- Alert dashboard: Shows active (unresolved) alerts with type, message, timestamp, and related order/item
- Resolve alert: Manager can mark an alert as resolved
- Alerts are generated by a background check (periodic polling or triggered on status change)

## 3. Out-of-Scope (Explicitly Excluded from MVP)

- **Payment processing / billing** — Requires payment gateway integration; out of 15-week scope
- **Customer-facing ordering (QR code menu)** — Adds user role complexity; MVP focuses on staff
- **Multi-restaurant / multi-tenant support** — Adds database partitioning complexity
- **Analytics dashboard (charts, reports)** — Nice-to-have but not core to DevOps demonstration
- **User authentication / role-based access** — Would require auth framework; MVP uses open access
- **Inventory / stock quantity management** — Beyond order management scope
- **Mobile native app** — Web-only MVP; responsive design covers tablet use
- **Email / SMS notifications** — Requires third-party service integration
- **Table layout / floor plan UI** — UI complexity beyond MVP
- **Recipe / preparation instructions** — Not core to order tracking

## 4. Technology Stack (Confirmed)

- **Frontend** — HTML5 + CSS3 + Vanilla JavaScript
- **Backend** — Java 17+ (Spring Boot)
- **Database** — MySQL 8.x
- **ORM** — Spring Data JPA (Hibernate)
- **Build Tool** — Maven 3.9+
- **Deployment** — Embedded Tomcat (via Spring Boot)
- **Testing** — Selenium WebDriver (Java bindings)
- **CI/CD** — Jenkins (Pipeline as Code) LTS
- **Containerization** — Docker + Docker Compose
- **Config Management** — Ansible (YAML Playbooks)
- **Version Control** — Git + GitHub
- **OS** — Windows (local dev)

---

## 5. MVP Acceptance Criteria Summary

The MVP is considered **complete** when:

- [ ] All 5 features (F1–F5) are functional and accessible via web browser
- [ ] Application runs locally on http://localhost:8080
- [ ] Application runs inside a Docker container
- [ ] At least 3 Selenium test cases pass
- [ ] Jenkins pipeline builds, tests, and deploys automatically
- [ ] Ansible playbook provisions a target node
- [ ] All weekly deliverables (Weeks 1–15) documented
- [ ] End-to-end pipeline demonstrated: Git commit → Jenkins → Selenium → Docker → Ansible
